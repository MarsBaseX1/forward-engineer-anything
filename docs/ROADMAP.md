# FEA 版本路线图

日期：2026-10-21。所有版本均为规划，尚未交付；按验收结果推进，不承诺日历交付时间。

## v0.1：Audit 与 CI 策略门禁

**用户价值：** 发布前发现一批可避免的信息暴露，并阻止已确认的风险回归。

范围限定为 Windows / macOS 上开发者提供的 Electron 发布资源目录。输入阶段为 `prepackage` 或 `developer-extracted`，必须记录；不宣称已覆盖最终安装包。

交付目标：本地 CLI、版本化配置、五类检查、JSON / SARIF、策略判定与公共合成夹具。CLI 命令为 `init`、`scan`、`verify`。CI 直接调用 CLI，首版不另建托管服务或专用 Action。

验收要求：

- 两个平台都验证同一组资源规则、空格 / Unicode 路径、权限不足、链接越界和畸形输入。
- 植入 source map、私钥格式候选、内部配置、调试符号和开发资产的夹具有明确预期结果；公开夹具识别率与误报统计。
- 候选密钥不主动联网验证；报告、日志和 SARIF 不出现植入的秘密原文，覆盖秘密处于内容、文件名、路径、键名和 URL 查询参数的夹具。原始文件清单不自动嵌入分享报告。
- 同一输入快照、规则和配置生成相同的规范化发现列表；时间戳与运行信息单独记录。
- 必需扫描项缺失、扫描超限、读取失败，以及声明必须展开检查的未支持容器，均不能得到成功退出状态。策略允许的不透明业务资源必须列出内部未评估；ASAR 根输入始终拒绝。
- `verify` 对比当前要求与旧报告逐项覆盖及规则版本；证据不足时要求重扫，并以验证时刻重新检查例外是否到期。只接收可信 CI 来源报告，不把自包含摘要当作真实性证明。
- 输入前提为可信且不并发修改的构建快照；拒绝特殊文件，不声称首版可抵御所有并发目录替换。
- 支持规则 / 路径 / 指纹粒度的例外、负责人、理由与到期日；策略可明确禁止指定规则。
- 验证真实 CI 命令的退出码与报告保留行为；敏感报告不会自动发布到公开页面。

不包含：读取原始 ASAR、安装器解析、原生逆向、代码签名验证、自动修改项目、AI 服务、通用加壳和运行时防护。

## v0.2：Protect 与平台完整性验证

**用户价值：** 将发现转为可审查、可恢复的构建改动，并检查最终产物。

新增受限制的 ASAR 只读适配器，检查归档与外置资源；选择 Electron Forge 作为第一条构建配置适配链。支持提出 source map / 调试资产分离与 ASAR 完整性配置补丁。其他构建系统先给出手动建议，不执行未知配置。

Windows 使用可信平台工具验证 Authenticode；macOS 在 macOS 主机验证 codesign、预期签名身份与适用的公证状态。主机能力不足或信任状态不可确定时标为未评估。签名 / 信任检查的联网需求必须显式声明，不能隐藏在离线扫描中。

平台输入限定为 Windows 解包应用目录中的 PE 文件与 macOS `.app`，不包含 MSI 安装内容解析或 DMG 挂载。对最终产物的结论必须列出具体格式；只有文件清单的安装器不能被描述为内容已完成安全检查。

验收要求：

- ASAR 解析覆盖畸形头、大小上限、链接、外置资源、重复路径与越界测试。
- 提议补丁限定到已支持的构建配置格式，展示修改内容与回滚方式；不运行目标项目配置来“读取配置”。
- 先修改与重建，再功能回归、封装签名、最终验证；不能直接修改已签名包后继续宣称原签名有效。
- 平台签名、完整文件清单和资源完整性分别出具证据；仅有签名字段不等于可信签名通过。
- 演示受信验证器对资源变更与错误发布者的拒绝行为；不将此描述为阻止所有本地篡改。
- 对受支持 Electron / 构建工具版本维护实测矩阵；新版本先标未验证，再补测试。

## v0.3：Arena、MCP 与授权参考应用

**用户价值：** 用相同任务与预算验证保护收益，向 AI 开发代理提供结构化证据。

新增只读 MCP 接口、演示授权 API、公开自有 Electron 应用的基线与改进构建，以及可选 REA 评测适配器。FEA 核心不依赖 REA；外部分析工具由使用者合法安装并固定版本。

验收要求：

- MCP 工具与 CLI 共享规则引擎，结果可对应；默认只返回必要的脱敏证据。
- 服务端针对主体、资源、租户、有效期、撤销和额度独立授权；未授权、跨租户、过期、撤销等固定用例均有独立测试。
- 自改演示客户端不能因此获得额外的服务端敏感操作权限；报告保留纯本地功能的剩余绕过边界。
- 同一业务源码提交、任务、模型 / 工具版本、预算与环境下，分别测量基线与改进版；每项默认至少 10 次独立运行并公开种子、失败与费用。
- 除公开演示任务，保留不参与调参的验证任务；不能只展示一次模型失败。
- 分别报告任务成功率、首次成功时间、实际费用、未成功的预算上限，以及启动 / 请求延迟、包体与合法用户失败情况。
- 超时记为预算内未成功；无依赖、环境故障和工具崩溃单列，不算保护成功。

## v0.4：原生适配与安全更新

按需求依次扩展 .NET、PE / Mach-O 与其他桌面框架；各适配器独立公布支持矩阵、覆盖范围与限制，不声称一个适配器支持全部语言或打包格式。

更新验证优先接入具有可信元数据、版本和过期机制的成熟框架。TUF 可作为参考与候选集成，需按目标产品验证回滚、冻结、密钥轮换与恢复；项目不自行设计密码协议。[TUF 官方概览](https://theupdateframework.io/docs/overview/)

## GitHub 发布准备

本设计资料仓库采用经所有者确认的 Apache-2.0，包含中英文介绍、项目图标和贡献指南。首次可执行版本发布前，还需确认维护者与安全报告渠道、CLI 与包名，完成至少一个真实端到端演示，并提供经过验证的安装和卸载说明。

发布首页必须分清“已经实现”“实验功能”和“规划”。没有独立审计时，不使用“安全认证”或类似措辞。基准报告公开所有权清晰的合成样本与复现步骤，私有目标的细节由软件作者管理。
