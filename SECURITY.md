# Security policy

## Supported release

Security fixes are provided for the latest published `1.0.x` release. Commands remain subject to the input, platform and evidence boundaries documented in their guides.

## Reporting a vulnerability

Use GitHub's **Security → Report a vulnerability** form when it is available for this repository. Include the affected FEA version, operating system, minimal reproduction, security impact and any suggested mitigation.

Do not place credentials, proprietary application artifacts, private reports, customer data or weaponized details in a public issue. If GitHub does not show the private reporting form, open a public issue containing only a short request for a private maintainer contact and no sensitive details.

Routine bugs, documentation corrections and feature requests can use the public [issue tracker](https://github.com/MarsBaseX1/forward-engineer-anything/issues).

## Scope reminders

FEA reports findings within documented formats and automates bounded configuration changes. A clean report is not proof that an application has no secrets or cannot be reverse engineered. Reports imported from outside a trusted build pipeline are not authenticated evidence.
